# 《巷战回声》

原创单人横版清关格斗游戏。拳过老街、夜市、工厂和屋顶，最后回到武馆守住街坊共同的家。

## 本地运行

需要 Node.js 20.19 及后续 20.x 版本，或 Node.js 22.12 及以上版本。

从 GitHub 克隆后，进入仓库目录，执行 `npm ci` 安装锁定版本的依赖，再执行 `npm run dev`。运行所需模型、纹理与许可均包含在 `public/`，不需要另行下载素材包。

~~~powershell
git clone https://github.com/Mesting42/xiangzhan-huisheng.git
cd xiangzhan-huisheng
npm ci
npm run dev
~~~

打开终端显示的本地地址。打包发布：

~~~powershell
npm run build
npm run preview
~~~

检查战斗判定、连续连段、真实模型骨架动作，以及敌人入场与章节衔接：

~~~powershell
npm test
~~~

开发运行时可打开 `/tests/visual/animation-review.html`，逐个查看三位角色的蓄力、命中与收招关键帧，或播放完整攻击、翻滚并切换朝向。

敌人模型对照位于 `/tests/visual/enemy-review.html`，可并排检查五类小兵、精英、五位头目与最终第二阶段。`/tests/visual/enemy-arena.html` 使用正式游戏的输入、AI、伤害判定和渲染，可切换三位角色，与单个敌人、Boss 或三组组合敌人交手；检查场使用 500 点气血方便观察，关闭章节推进，不写入主线通关进度。

游戏资源在构建时从本地 three 依赖打包；运行时不访问 CDN、不请求远程图片、字体、音效或服务。

## 流程与内容

- 五个完整章节：武馆前的老街巷、灯火夜市、废弃工厂、雨夜屋顶、武馆决战。
- 每章按固定顺序经过三段各有编排的战斗区域，最后与该区域头目交手；最终头目有两种战斗阶段。
- 每波开始前有脚步与左右来敌提示，敌人从镜头外按间隔交替跑入；入场期间不主动攻击，可以被玩家拦截。清场后稍作喘息，玩家保留原位置。头目单独走入战场，介绍横幅保留战场视野；最终头目的支援也沿场边进入。
- 三位原创可操作角色：林岚（平衡连拳）、乔小满（快速连打与翻滚）、铁山（重击、擒拿和击飞）。新角色随主线解锁，练功房可提前试用。
- 五类普通敌人：快手、扛把子、护手、掷手、撞街客；较难章节会编入精英敌人。
- 第一关提供可跳过的动作提示。练功房没有计时和受伤压力，木人会持续站起。
- 每关显示通关评价、分数、用时、受伤、连击和回声印奖励；可重玩已开放章节。通关记录及解锁内容留在本机。
- 三档难度通过攻击频率、敌人编组、预警时间和容错进行区分。街坊相助会给新玩家更宽的反应空间。
- 故事结尾收束为武馆守住、街坊留下的完整结局；通关后可重新挑战更高难度。

| 轻击与连拳 | J | A |
| 重击、破防 | K | X |

| 翻滚（默认向前，有方向输入时按该方向） | L | B |

### 短棍投掷

先打碎路障、靠近掉落短棍按 `E` 拾取，再按 `G` 投掷。空手按 G 会显示拾取提示。持棍时手中有实物，HUD 显示剩余次数、秒数和投掷键。

投掷有 0.18 秒起手和后续恢复，短棍实际离手飞行；起手被打断时保留未掷出的短棍。命中同一纵深的敌人会扣血、破防和击退；一次投掷只命中一个目标，不返还能量。林岚标准伤害为 38，随角色力量和难度调整，Boss 仍按既有减伤规则结算。飞行采用连续路径碰撞并检查高度，越过敌人头顶或纵深错开不会命中。

### 敌人数值与挑战

标准难度采用以下基础数值。普通敌人可以承受任意角色一套基础轻拳连段；重击、追击、绕背与翻滚反击用于继续压制。

| 敌人 | 生命 | 基础伤害 |
| --- | ---: | ---: |
| 快手 | 100 | 14 |
| 扛把子 | 190 | 26 |
| 护手 | 145 | 18 |
| 掷手 | 96 | 15 |
| 撞街客 | 140 | 22 |
| 街口硬茬 | 240 | 24 |
| 钢牙梁 / 红袖鸢 / 炉锤 / 断弦 / 周啸天 | 840 / 960 / 1140 / 1260 / 1520 | 22 / 20 / 30 / 25 / 28 |

Boss 的稳势重招和第二阶段追招可能在基础伤害上增加伤害。标准难度缩短出手冷却与群体调度间隔，保留可读的预警和受击保护。“街坊相助”调整为 1.25 倍玩家伤害、0.6 倍敌方伤害和较宽松预警；“武馆试炼”通过双近战出手、更密集远程压力和较短冷却加强挑战，生命仅比标准增加 12%。已有存档选择会保留，可在角色选择页切换难度。

触屏布局提供虚拟摇杆、轻击、重击、跳跃、翻滚、绝招和终结按钮；靠近补给会自动拾取。触屏可用右侧的圆形攻击键连续操作，摇杆灵敏度可在设置中调整。

## 桌面、平板与手机适配

手机以横屏作为主要游玩布局。横向战场可更早展示两侧敌人、投掷与突进预警，左右手操作区也更宽。竖屏保留完整玩法，菜单提供可关闭的横屏建议；竖屏战斗将顶部状态、中央战场和底部操作区分别排布。

- 触屏提供轻拳、重击、跳跃、翻滚、绝招、终结、拾取、投棍八个按钮，主要按键至少 44 CSS 像素。横屏将拾取与投棍安排在摇杆右侧，竖屏安排在攻击区第三排。
- 平板横竖屏均显示触控；带触屏的大尺寸设备也可根据触控能力显示按钮。
- 菜单、选人、设置、暂停、结算可独立纵向滚动。手机选人使用整行卡片；小屏结算使用两列；设置页不会要求横向滚动。
- 屏幕旋转会自动暂停并清空输入，点击继续后恢复；摇杆具有独立指针归属，其他手指不会抢占摇杆。同一按钮的多个触点分别跟踪，松开一个触点不会错误释放另一个触点。
- 触控灵敏度支持 40%–150%，以 1% 调整并保存在本机。菜单中的滑杆和按钮保留原生方向键、空格操作。
- 场景渲染根据实际画布区域变化更新尺寸，支持动态窗口高度与安全区间距。

开发模式可打开 `/tests/visual/responsive-review.html`，切换 13 个正式 UI 状态检查排版。该检查页隔离主线存档，结算与结局使用明确标注的布局样本，不能用来证明实际通关。本轮七种尺寸的 91 组布局检查、截图和实测范围见 `qa-screenshots/responsive-2026-10-20/verification.md`。

玩家攻击按朝向、攻击帧、纵深和高度判定。轻击衔接为角色专属连段，重击可破防；命中积累气劲。敌人的橙色预警对应突进、重击或投掷，留出翻滚和反击时间。玩家受击后会有短暂保护。短棍只能挥击少量次数或限时携带，徒手战斗仍是主轴。

翻滚包含收身、整圈转动、落地和恢复，位移随动作连续推进。翻滚的中段避伤，起手和落地有风险；擦身避开一次实际攻击会给予短暂反击机会，落地后按轻攻击使出破防反击。三位角色的翻滚距离和用时随身法有所区别，乔小满的保护窗口更宽；空中不能开始地面翻滚，撞到场边也会正常结束动作。键盘、手柄 B 和触屏“翻滚”按钮使用同一套逻辑。

## 战斗分支与敌方博弈

| 路线 | 用途 |
| --- | --- |
| 连续轻击 | 角色原有的稳定连拳，各角色段数不同 |
| 轻 → 重 | 截势破防，伤害较低、收招较快 |
| 轻 → 轻 → 重 | 挑空追击，可跳跃取消收招，再接空中攻击 |
| 铁山直接重击 | 近身擒住普通敌人，过肩投出；投出的敌人可撞伤其他敌人 |
| 擦身翻滚 → 轻 | 获得一次破防反击，较容易积累 Boss 失衡 |

攻击有约 0.16 秒短输入缓冲，命中停顿期间的指令也会保留。命中或打在防守上后，部分招式可以衔接重击或翻滚；技能取消需要实际命中。重击挥空需要完成恢复，无法立即取消所有风险。每个敌人最多承受三段连续浮空命中，随后强制落下并短暂保护。护手的正面防守可以破防，也可以绕到背面处理。

普通拳脚每次攻击最多回复 14 点气劲；绝招和终结技不返还能量。乔小满的穿巷步会实际向前突进；三位角色的终结技分别是守馆终章、回燕双旋和山门震落，具有不同的攻击时机、范围和打击次数。回声变招的绝招消耗为 40 点，默认绝招为 35 点，终结技消耗 100 点。

群战按攻击名额和时间间隔调度：标准与休闲难度同时最多一个近战敌人出招，试炼可有两个；远程投掷另有间隔和在场弹数上限。等待中的敌人调整站位，护手尝试挡在掷手前方，突进者保持助跑距离。敌人之间会分离，避免完全重叠。

敌人的突进为连续移动，起手前半段跟踪、后半段锁定路线；锁定后不会突然转身追踪玩家。地面的长条、窄线、横带和圆环分别对应冲撞、投掷、横扫和砸地。砸地可跳跃躲避；横扫适合沿纵深换线。淡绿色地面环表示 Boss 的恢复或失衡窗口。

五位 Boss 都有至少三种可辨认的攻击模式。钢牙梁组合短拳、摆臂与冲撞；红袖鸢交替扫腿、突步和投掷；炉锤使用压进、横抡和砸地；断弦通过摊掌虚步与收拳实招形成真假起手；周啸天第二阶段会把横扫接追掌，第一次收势不代表连段结束。

Boss 稳势蓄力和关键攻击仍正常扣血，但不会被每次轻拳打断。重击、反击与终结技积累失衡，满槽进入固定反击窗口，连续命中不会无限延长这个窗口。普通收招阶段更容易失衡，伤害收益也更高。Boss 倒下后会清除敌方飞行物、待入场支援和残余支援，结束战斗。

练功房有连招与追击、翻滚反击、Boss 失衡三个项目，并显示目标完成情况。陪练会正常出招，玩家不损失气血；练习不会写入主线成绩。

`npm test` 包含独立规则、真实蒙皮网格和 45 组章节战斗推进检查（三名角色 × 三档难度 × 五关）。章节自动检查使用受伤保护来隔离流程与平衡问题，不能代替真人难度评估；实际攻击、位移、AI、结算与解锁仍走正式逻辑。

## 设置和存档

设置包括画质、特效强度、镜头震动、降低闪屏、音乐和音效音量、触控灵敏度及按键重设。音乐和音效由 Web Audio 程序合成，无需音频素材。浏览器失焦、暂停和进入菜单时都会清除输入状态；失焦期间游戏暂停。

进度、角色解锁、章节记录、难度与设置保存在浏览器本地存储。读取失败或存档损坏时仍可开新档。设置页的“重置本机存档”会先说明清除范围，再要求再次确认。

## 项目结构

- src/game.js：章节流程、玩家状态、敌人 AI、拾取物和战斗循环。
- src/combat.js：可独立验证的战斗帧、朝向、车道、格挡和评价规则。
- src/battle-rules.js：命中取消、连招分支、翻滚保护、能量上限、群体进攻名额、站位和连续冲撞判定。
- src/boss-brain.js：五位 Boss 的距离与阶段选招、虚招、连段与失衡阈值。
- src/enemy-entry.js：分批入场编排、镜头外出生、连续移动、拦截与入场完成判定。tests/enemy-entry.test.js 覆盖五章三档难度、不同屏幕比例、头目入场和暂停恢复。
- src/renderer.js：Three.js 镜头、分关场景、人物模型与动作、预警和粒子。
- src/fighter-animation.js：按招式命中时间驱动的骨骼动作、手脚目标与双骨骼求解。
- src/enemy-models.js、src/enemy-animation.js：敌人和 Boss 的体型衣装、配件配置，以及预警、攻击、格挡、收招与受击动作。
- src/enemy-costumes.js：敌方衣装剪裁、脸型、独立发型，以及保安帽、安全帽、反光条、口罩、眼镜和工装等随骨骼运动的配件。
- src/input.js：键盘、手柄、触控和输入状态清理。
- src/audio.js：程序合成的主题氛围音乐与战斗音效。
- src/ui.js、src/style.css：中文菜单、战斗 HUD、结算页和响应式触控布局。
- src/save.js、src/data.js：本地存档、角色数据、敌人数据与章节编排。

## 人物模型与许可

三位玩家角色、五类小兵、精英和五位 Boss 均使用本地 Quaternius Universal Base Characters 骨架与头部，搭配同作者、兼容骨架的 Modular Character Outfits - Fantasy Peasant 或 Ranger 衣装。头部由基础角色网格的蒙皮权重提取，衣装使用兼容骨架。敌方对头部轮廓、下摆长度和宽体比例进行几何调整，衣服采用独立材质与裁片，隐藏原有兜帽、肩甲、皮革护腕和双腰带，并绑定原创现代服装配件；修改发生在克隆模型上，不会改变玩家或原始 CC0 文件。

快手为瘦身短夹克与窄脊发型；扛把子为宽腹光头、工装背心与卷袖；护手穿深蓝保安制服，佩戴帽徽、护膝与手套；掷手戴针织帽和口罩，配斜挎工具包；撞街客戴安全帽、穿反光背心；精英使用削边发型、眼镜和翻领短外套。钢牙梁为宽肩光头、链饰与厚夹克；红袖鸢为不对称短发与短外套；炉锤配安全帽、呼吸防护和围裙；断弦为高瘦长外套与束发；周啸天为背头、眼镜与西装领带，第二阶段改变衣装色彩。

攻击包含蓄力、命中时的实际手脚伸展和收招，肩肘、髋膝根据手脚目标求解，动作峰值对齐碰撞判定的起手时间。普通与精英敌人的头顶血条在存活时始终显示，正对镜头，受伤后显示血量缩减与短暂伤害残留；击败和切换场景时随敌人清除。

敌方动作直接读取 AI 的 windup、strike 和 recover 计时：预警期间保持可辨认的起手，实际判定时到达出拳、撞肩、踢击、投掷或砸地姿态，随后回到防守。体型的非等比调整由模型空间的骨骼求解支持，避免宽体角色的手脚在攻击时扭曲。
